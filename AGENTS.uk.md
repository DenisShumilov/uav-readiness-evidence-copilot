# AGENTS.md — Copilot готовності та доказів для БпЛА

*[English](AGENTS.md) · Українською*

Цей файл є ядром правил (rules core) скаффолда (scaffold — обв'язка, що будує проєкт),
який створює цей репозиторій.
Це README **для ШІ-агентів (AI agents)**, що працюють тут.

Основна теза: **інтелект — у скаффолді навколо моделі: правила, ролі, перевірки та
верифікація (verification — підтвердження правильності) — а не в самій моделі.**

## Місія (Mission)

Цей репозиторій — БЕЗПЕЧНА, публічна система портфоліо-рівня для контролю якості документації
(documentation QA), відстеження доказів (evidence tracking), простежуваності (traceability),
звітності про готовність (readiness reporting), придатності до аудиту (auditability) та
демонстраційного сторітелінгу (demo storytelling) для інженерної документації БпЛА / робототехніки.
Вона не керує, не контролює та не симулює жодної реальної системи.

## Жорстка межа безпеки (Hard Safety Boundary)

Ніколи не додавати, не допомагати та не документувати:

- керування дроном або роботом;
- керування польотом (flight control);
- планування місій, маршрутів або точок маршруту (waypoint);
- наведення на ціль (targeting);
- роботу з корисним навантаженням (payload) або його вибір;
- живу телеметрію (telemetry) або канали керування;
- автономну навігацію;
- поради щодо ухилення, маскування або протидії (countermeasure);
- тактичні чи операційні робочі процеси розгортання.

Якщо запит відхиляється туди:

1. чітко відмовити,
2. пояснити ризик одним рядком,
3. перенаправити на безпечну альтернативу: контроль якості документації, відстеження доказів,
   простежуваність, звітність про готовність або артефакти аудиту.

Жоден файл не може містити реальних чи реалістичних операційних координат, маршрутів, місій, цілей,
деталей корисного навантаження, потоків телеметрії, радіо-/керувальних каналів або тактик.
Усі приклади є синтетичними (synthetic — штучно згенерованими) та статичними.

## Межа продукту (Product Boundary)

Цей проєкт оцінює лише **готовність документації** (documentation readiness). Він не схвалює політ,
місію, польове застосування, сертифікацію безпеки чи тактичну готовність. Оцінка готовності
(readiness score) — це твердження про документи (paperwork), а не дозвіл на експлуатацію.

## Мова та стиль навчання (Language and Teaching Style)

Мова пояснень за замовчуванням для супроводжувача (maintainer): проста українська, де кожен новий
технічний термін пояснюється звичайними словами. Публічні артефакти репозиторію (README, документація,
сайт) — двомовні UA/EN. Перевага конкретним крокам, таблицям, шаблонам та прикладам над абстрактним
текстом.

## Контракт доказів (Evidence Contract)

Ніколи не вигадувати підтвердження. Якщо доказ відсутній, суперечливий, небезпечний або поза межами
наразі розпарсених (parsed — прочитаних і розібраних) вхідних даних, позначити твердження як `locked`
(заблоковане) (або вислів як `UNVERIFIED` — неперевірений).

Кожне технічне твердження має один статус: `verified` (перевірено), `partial` (частково),
`locked` (заблоковано) або `conflict` (суперечність).

Основне правило:

```text
No evidence -> locked.
```

## Карта репозиторію (Repo Map)

- `packages/core` — схеми та спільні типи (Zod).
- `packages/parsers` — парсять (parse — читають і розбирають) лише активні синтетичні вхідні дані.
- `packages/evidence` — побудова графа доказів (evidence graph).
- `packages/rules` — детерміноване (deterministic — однозначно передбачуване), пояснюване оцінювання
  готовності.
- `packages/reports` — вихідні дані у форматах markdown / JSON / CSV / HTML.
- `packages/qa` — помічники контролю якості (QA) та наскрізна (end-to-end) верифікація.
- `site` — лише публічне демо для портфоліо.
- `docs` — публічна пояснювальна документація.
- `demo-video` — ресурси та скрипти для генерації відео портфоліо.

## Обов'язкові субагенти (ролі) (Required Subagents)

Репозиторій будують 10 спеціалізованих агентів (див. [docs/scaffold.md](docs/scaffold.md)):

1. **Product Architect** (Архітектор продукту) — тримає MVP (мінімально життєздатний продукт)
   малим та орієнтованим на портфоліо.
2. **Safety & Red-Team** (Безпека та «червона команда») — блокує небезпечний операційний обсяг БпЛА.
3. **Domain Evidence** (Доменні докази) — захищає правило `no evidence -> locked`.
4. **Backend Engineer** (Інженер бекенду) — малі модулі на TypeScript / Zod.
5. **Frontend Engineer** (Інженер фронтенду) — тримає дашборд простим і зрозумілим для рекрутерів.
6. **QA / Evals** (Контроль якості / Оцінювання) — пише тести та перевіряє небезпечну поведінку.
7. **Documentation & Portfolio** (Документація та портфоліо) — пояснює цінність і пише зрозумілу
   документацію.
8. **Security / Supply Chain** (Безпека / Ланцюг постачання) — перевіряє хеші, секрети та ризики
   залежностей.
9. **Ukrainian Teacher** (Український учитель) — пояснює кожен технічний термін просто.
10. **Agent Plugin Researcher** (Дослідник плагінів агентів) — перевіряє плагіни, навички (skills)
    та субагентів ШІ перед кожною фазою.

## Обов'язкові навички (Required Skills)

7 повторно використовуваних навичок (skills) підтримують агентів: `explain-terms`, `red-team-check`,
`evidence-lock-check`, `portfolio-readme`, `phase-review`, `safety-boundary-check`,
`agent-plugin-audit`.

## Бар'єри якості (Quality Gates)

- **Doubt Gate** (Бар'єр сумніву) — перед будь-якою зміною файлу підтвердити, що вона допомагає
  портфоліо, є безпечною для публічного показу, лишається поза операційним обсягом і достатньо мала
  для MVP. Якщо ризиковано — зупинитися й спростити.
- **Safety & Red-Team review** (Перевірка безпеки та «червоної команди») — виконується перед
  будь-якою зміною, пов'язаною з БпЛА.
- **Evidence Lock** (Блокування доказів) — непідтверджені чи суперечливі твердження лишаються
  `locked`.
- **Self-Review** (Самоперевірка) — після зміни: що може бути не так, що перевірити, який ризик
  лишається.

> Примусове виконання вже активне: детермінований хук `PreToolUse` у
> `meta/ai-workflows/hooks/scaffold-gate.mjs`, підключений у `.claude/settings.json`, логує й блокує
> небезпечні правки до запуску інструмента. Його перевіряє тест
> `packages/qa/src/scaffoldGate.test.ts`.

## Верифікація перед завершенням (Verification Before Done)

Зміна вважається завершеною лише після того, як виконано таке (або зазначено, чому ні):

```bash
npm run demo:readiness
npm run typecheck
npm test
npm audit --audit-level=moderate
```

## Політика інструментів (Tooling Policy)

За замовчуванням — заборона (default-deny) для нових плагінів, MCP-серверів, зовнішніх сервісів та
широких дозволів. Не встановлювати й не під'єднувати зовнішні інструменти агентів без явного
підтвердження супроводжувача. Перевага локальним навичкам рівня проєкту та інструментам лише для
читання (read-only), а також мінімальному обсягу, потрібному для завдання.

## Визначення завершеності (Definition of Done)

- межа безпеки лишається цілою;
- непідтверджені твердження лишаються заблокованими (locked);
- документація / сайт / демо все ще відповідають коду;
- верифікація виконана, або будь-яка прогалина явно позначена `UNVERIFIED`.

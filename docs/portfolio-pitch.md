# Portfolio pitch

## CV bullet

Built a safe TypeScript documentation readiness tool for UAV and robotics QA workflows, including evidence parsing, evidence locks, traceability matrix export, readiness scoring, artifact hashes, automated tests, and a recruiter-friendly portfolio demo page.

## LinkedIn post draft

I built a portfolio project called UAV Readiness & Evidence Copilot.

It is not a drone control tool. It is a safe engineering QA workspace that checks documentation, connects claims to evidence, marks missing proof as locked, and generates readiness outputs.

The demo reads synthetic files, builds an evidence graph, calculates a readiness score, exports a traceability matrix, creates file hashes, and writes a 30-second portfolio page.

What I wanted to show:

- evidence-first engineering thinking;
- safe AI-assisted workflow design;
- TypeScript, Zod, Vitest, and CLI implementation;
- clear boundaries around what the system must not do.

## GitHub pinned repo description

Safe TypeScript UAV documentation QA demo: parsers, schemas, evidence graph, readiness score, traceability CSV, artifact hashes, tests, and 30-second portfolio page.

## Interview explanation 1 - simple

This project is like a paperwork inspector for engineering documents. It checks which claims have proof, which are only partly supported, and which must stay locked because proof is missing.

## Interview explanation 2 - technical

The project uses TypeScript schemas, parsers, an evidence graph, readiness rules, and report generators. The CLI reads safe synthetic fixtures and outputs markdown, JSON, CSV, and hash manifests with automated tests.

## Interview explanation 3 - safety-focused

I designed the project around strict safety boundaries. It supports documentation QA and audit readiness, but it does not include operational UAV control, live telemetry, route planning, targeting, payload handling, or tactical advice.

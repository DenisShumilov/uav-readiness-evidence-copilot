# Локальний аналізатор якості телеметрії

Версія клієнтського контуру: 20.10.2026. Python 3.9+, лише стандартна бібліотека, без завантаження даних у мережу. Приймає **саме переданий файл**, генерує український Markdown-звіт; JSON доступний додатково.

```sh
python3 engines/telemetry_ew/telemetry_analyzer.py --input /path/client.ulg --report /path/report.md --json /path/report.json
python3 engines/telemetry_ew/telemetry_analyzer.py /path/client.csv
python3 engines/telemetry_ew/telemetry_analyzer.py --self-test
```

За відсутності `--report` результат записується поряд із входом як `<file>.report.md`. Каталог результату має існувати. Коди завершення: **0** — підтримувані записи прочитані (див. попередження про часткове семантичне покриття); **2** — помилка входу/розбору/запису; **1** — провал self-test. На помилці розбору записується діагностичний звіт з частковою статистикою; відсутній/надмірний/недоступний файл повідомляється у stderr. Вхід не перезаписується, включно з symlink/hardlink на нього.

| Формат | Підтримано | Межі |
|---|---|---|
| Обгортка GZIP `.gz` | Однокомпонентне (single-member) розпакування до 256 MiB із перевіркою завершеності потоку (`eof`), CRC32/ISIZE та відсутності зайвих байтів | Багатокомпонентні GZIP, обрізані потоки без trailer та архіви понад ліміт відхиляються з кодом 2 |
| PX4 `.ulg` / `.ulog` | F-схеми, A/R-підписки, D-дані; примітивні типи, масиви, вкладені/forward-defined типи, необов'язковий кінцевий padding; перевірка цілочисельного типу `timestamp` (у мкс) та відсутності дублікатів полів у схемі | Версії 0/1. Ненульові `incompat_flags` (зокрема appended data) та пошкоджені I-пакети відхиляються явно. Поля зберігаються в одиницях записаної uORB-схеми |
| ArduPilot `.bin` | Справжні FMT, dynamic message IDs, поля з типами a/b/B/g/h/H/i/I/f/d/n/N/Z/c/C/e/E/L/M/q/Q; вбудовані FMT-масштаби, перевірка числового типу `TimeUS`/`TimeMS`, порядконезалежне зіставлення `FMTU`/`UNIT`/`MULT` у `schema_units` | Множники `FMTU`/`MULT` публікуються у `schema_units` JSON (додаткове перемасштабування самих значень не виконується). Однойменні повідомлення різних сенсорів агрегуються разом. Невідомий тип без FMT/втрата синхронізації/обрізаний запис — явна помилка |
| u-blox `.ubx` | Fletcher checksum кожного кадру; `NAV-PVT` (84/92 байти), `NAV-SAT` v1 (із часовою шкалою `iTOW`), `NAV-STATUS`, `NAV-DOP`, `MON-HW` (60 байтів зі зміщенням `jamInd=45` та 68 байтів зі зміщенням `jamInd=53`); дійсність `fix`/`invalidLlh`, `hMSL`/`ellipsoid` окремо, `pDOP` і NED velocity | Решта класів/ID рахуються як непідтримані, не декодуються. Змішані UBX/NMEA потоки відхиляються. `iTOW` має тижневий rollover; він може відобразитися як зворотний час |
| MAVLink `.tlog` / `.mavlink` | Фреймінг v1 (`0xFE`, фіксована довжина) та v2 (`0xFD`, легальне усічення кінцевих нулів, перевірка `incompat_flags`), опційний 8-байтовий timestamp-префікс `.tlog`, перевірка CRC-16/MCRF4XX для 8 відомих `CRC_EXTRA`, розділення потоків за `(sysid, compid)`; семантика `#24 GPS_RAW_INT` (безрозмірний `hdop`, sentinel `255` супутників -> `missing`) та `#33 GLOBAL_POSITION_INT` | Невідомі `incompat_flags` та вкорочені v1-пакети відхиляються. Для невідомих `msg_id` поза таблицею `CRC_EXTRA` та для підписів v2 без ключа формується явне попередження у `quality` |
| NMEA `.nmea` | `GGA`/`RMC`/`GSA`/`GSV` з різними talker ID, XOR checksum, градуси/хвилини, швидкість з вузлів у м/с, невалідний fix як відсутні координати, перевірка повноти 4-польових груп супутників у `GSV` | Без checksum — явне попередження; обрізана група супутників `GSV` — помилка. Речення не зшиваються в синхронізовані епохи; інші типи рахуються окремо |
| CSV `.csv` | UTF-8/BOM, кома/крапка з комою/tab, унікальний заголовок, порожні й текстові значення, min/max числових колонок, скінченна похідна статистика (`max_step`, `max_rate_per_s`) | Десяткова крапка; одиниці задаються назвами/схемою користувача. Час: `timestamp_s`/`time_s`, `*_ms`, `*_us`, `TimeUS`/`TimeMS`. Вхідні або похідні `NaN`/`Infinity` — явна помилка |

Звіт містить SHA-256 переданих байтів, кількість записів, порожні присутні значення (`missing`), відсутні у записі ключі (`absent`), покриття (`coverage`), діапазони полів, часові розриви/повтори, непідтримані типи та конкретні помилки. CRC відсутній у самих ULog/DataFlash: перевірка структури не доводить відсутність усіх пошкоджень.

Діапазони — факти про декодовані дані, а не допуски чи оцінка справності. Причину втрати фіксу та глушіння/спуфінг цей інструмент **не встановлює**. C/N0, баровисота, airspeed чи дата не вигадуються. Немає порівняння із вимогами конкретного виробу без заданих критеріїв. Звіт може містити координати: автоматичної анонімізації немає.

Обмеження ресурсу: файл до 256 MiB, до 4096 потоків, до 4096 полів на потік, вкладеність схем до 16. Вхід читається локально в пам'ять; для великих файлів потрібен штатний експорт/розбиття. Скрипт не виконує код або команди з полів файлу.

## Верифікація

Вбудований набір `python3 engines/telemetry_ew/telemetry_analyzer.py --self-test` та `engines/telemetry_ew/test_readiness.py` містять самодостатні синтетичні протокольні фікстури й CLI-перевірки підтримуваних форматів, неправильних checksum, обрізаних/порожніх файлів, рекурсивних схем, неправильних типів часу, `invalidLlh`, CSV `NaN` та захисту входу від перезапису. Будь-які зовнішні порівняння зі сторонніми польотними логами (`pyulog` / `DFReader`) не входять до цього автономного репозиторію і без прикладеного пакета доказів мають статус `UNVERIFIED`.

## Історичні матеріали

`sample_ardupilot.bin`, `sample_px4.ulg`, `sample_ublox.ubx`, `sample_uav_ew_flight.nmea`, `SAMPLE_TELEMETRY_EW_REPORT.md` та `sanitize_telemetry.py` походять із попереднього демонстраційного контуру. Їхні штучні бінарні схеми й причинні висновки не є доказом сумісності чи детекції; клієнтський аналізатор їх не використовує. Допоміжний скрипт `sanitize_telemetry.py` виконує лише фіксований зсув координат для вузького набору перевірених схем і відхиляє непідтримувані або пошкоджені файли; він не є сертифікованим засобом OPSEC/деідентифікації.

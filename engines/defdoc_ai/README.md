# DefDoc AI: локальна перевірка клієнтського документа

Перевірка одного `.docx`, `.xlsx`, `.md` або `.txt` однією командою з кореня репозиторію:

```sh
python3 engines/defdoc_ai/defdoc_auditor.py "/шлях/ТУ.xlsx" --report "/шлях/звіт.md"
```

Альтернатива: `--input "/шлях/ТУ.xlsx"`. Без `--report` поруч із входом створюються `ТУ.audit.md` і `ТУ.audit.json`. Звіт українською; JSON містить ті самі докази, SHA-256, повний шлях, адреси рядків/комірок, застереження та результати. Файли входу не змінюються. Мережевих запитів немає; залежності — Python 3.9+ stdlib.

Порівняння документів, які справді надані:

```sh
python3 engines/defdoc_ai/defdoc_auditor.py --tu "/шлях/ТУ.docx" --passport "/шлях/Паспорт.md" --pmv "/шлях/ПМВ.xlsx" --report "/шлях/звірка.md"
```

Відсутні документи не замінюються демонстраційними. Розпізнані таблиці мають заголовки `Параметр | Норма | Факт` (можлива колонка `Одиниця`) або `Параметр | Значення` для попарного порівняння між явно позначеними `ТУ`, `Паспортом` та `ПМВ` (включно з прямою звіркою `Паспорт ⇄ ПМВ`). Якщо таблиця не має стандартного заголовка, використовується фізично-розмірнісна евристика (`AUTO-SCHEMA-PHYSICS`) для рядків із явною умовою/нормою та виміряним фактом. Підтримуються: явні скаляри з відомими одиницями СІ (`=`, `<`, `>`, `≤`, `≥`, «не більше», «не менше»), симетричні допуски (`X ± Y`), інтервали (`від X до Y`, `X..Y`), частотні піддіапазони та списки комплектності (`Назва — N шт.`). Записи з явними запереченнями («не перевірено», «підтвердження відсутнє»), нерозібраними умовами, дублікати параметрів у межах одного документа, суперечливі колонки одиниць або відсутні фактичні значення дають `UNVERIFIED`, а не вигаданий `PASS`.

DOCX: текст збирається зі всіх runs основних абзаців і прямих таблиць, адреса — `word/document.xml`, номер таблиці/рядка. Об’єднані клітинки (`gridSpan`/`vMerge`) та відстежувані зміни (`w:ins`/`w:del`) не дають автоматичного `PASS`. XLSX: усі аркуші за relationships, shared/inline/rich strings, числові та булеві комірки, збереження пропусків колонок, перевірка координат рядків і дублікатів адрес. Для формул XLSX виконується безпечне детерміноване обчислення обмеженої граматики (`+`, `-`, `*`, `/`, `SUM`, `MIN`, `MAX`, `AVERAGE`, посилання на комірки й діапазони) у порядку залежностей із перевіркою розбіжності між `<f>` та кешем `<v>` (`CYBER-XLSX-CACHE`); непідтримувані функції або нерозв'язані посилання дають `UNVERIFIED`. Ліміти: 64 MiB на вхід, 128 MiB розпакованого ZIP, 32 MiB на частину, 30000 непорожніх рядків, 500000 розгорнутих XLSX-комірок. Перевищення лімітів/пошкодження — код виходу 2; сформований звіт — 0 незалежно від наявності FAIL (статуси у MD/JSON).

Звіт зберігає вихідний текст локально: він **не є автоматично знеособленим**. Наявний `sanitize_doc.py` — окремий допоміжний інструмент токенізації за регулярними виразами, а не гарантія видалення всіх чутливих даних. Перед передачею звіту потрібен перегляд.

Перевірки:

```sh
python3 engines/defdoc_ai/defdoc_auditor.py --test-client
python3 engines/defdoc_ai/defdoc_auditor.py --benchmark
python3 engines/defdoc_ai/defdoc_auditor.py --self-test
```

`--test-client` запускає регресії клієнтського читання, порівняння, помилок та захисту від хибних PASS. `--benchmark` запускає синтетичний корпус `BM-01..BM-15` та граничні випадки `FN-01..FN-02` (17 сценаріїв: 14 позитивних виявлень дефектів, 1 чистий контрольний пакет, 2 `UNVERIFIED` граничні випадки) та перевіряє точність кожного сценарію. `--self-test` — лише старий синтетичний сценарій (генерує demo-файли, бандл і демонстраційні патчі у `sample_data/`). Його readiness score не оцінює реальні файли; параметри експорту/авто-патчингу/бенчмарку заборонені разом із клієнтським входом. Запуск без входу та без явного тестового режиму завершується usage error.

### Межі застосування та вимоги до верифікації

- Потрібен реальний знеособлений пакет і підтверджені критерії клієнта: довільні шаблони та нестандартні доменні правила потребують окремих правил і тестів. Нерозпізнаний текст залишається доступним у доказовому витягу зі статусом `UNVERIFIED`.
- PDF/OCR, вкладені DOCX-таблиці, колонтитули, виноски, зображення, цифрові підписи, правова відповідність і справжність вимірювань не перевіряються. Потрібен перегляд відповідального інженера.
- XLSX-дати й одиниці у форматах комірок (`numFmtId`) не інтерпретуються. Складні табличні формули поза базовою граматикою позначаються `UNVERIFIED` і потребують перерахунку в табличному редакторі; жодних автоматичних змін результатів клієнтських випробувань не виконується.

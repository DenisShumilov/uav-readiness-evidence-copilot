# 60-second storyboard - English

## 0-10s - Problem

Screen: GitHub README and demo screenshot.

Say: Engineering teams can have scattered artifacts, notes, logs, and claims. It is hard to see what is actually supported by evidence.

## 10-20s - Open portfolio demo

Screen: `examples/demo-uav-readiness/output/portfolio-demo.en.html`.

Say: This is a safe documentation QA demo, not a drone control tool.

## 20-35s - Score and counters

Screen: readiness score and evidence counters.

Say: The page shows a documentation readiness score and counts for verified, partial, and locked evidence.

## 35-45s - Locked steps and warnings

Screen: warnings and locked steps.

Say: Missing proof stays locked, so the tool does not invent confidence.

## 45-55s - Outputs

Screen: generated outputs list.

Say: The CLI generates reports, evidence graph JSON, traceability CSV, and artifact hashes.

## 55-60s - Safety and value

Screen: safety boundary.

Say: The value is safe engineering QA: evidence tracking, traceability, and readiness reporting for documentation workflows.
